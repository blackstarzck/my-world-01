# Revision N — 전시장 입장 전 로딩 UI

2026-10-19 KST. 기존 아이보리 배경과 테라코타 강조색에 맞춰 SVG 아치 드로잉, 로고 점의 미세한 움직임, 이동하는 대기 바를 추가했다. 별도 이미지·영상·애니메이션 라이브러리나 지속적인 JavaScript 프레임 루프는 추가하지 않았다.

진행률 백분율 대신 실제 준비 단계를 표시한다.

1. **공간:** Gallery 모듈, 모델 및 표면 자료를 불러오는 동안.
2. **빛과 작품:** 모델 이후 환경과 작품 텍스처의 준비를 확인하는 동안.
3. **입장 준비:** 모든 필수 자산 확인 후 텍스처 업로드·기하·효과·셰이더를 준비하는 동안.

기존 실제 첫 composer 제출의 `onReady` 조건을 보존했다. 준비가 끝난 뒤 덮개만 360ms 동안 사라지며, 애니메이션을 보여 주기 위한 최소 대기 시간은 없다. 기존 진단 이름 `loading-ui-dismissed`는 이제 장면 준비 완료/덮개 페이드 시작 시각을 가리킨다. 이 시각을 덮개가 완전히 보이지 않는 시각이라고 보고하지 않는다.

이미지 관람으로 건너뛰기, 오류 시 대체 관람과 3D 재시도를 보존한다. 로딩 중 배경 UI와 캔버스는 `inert`이며 작품 방향키 조작도 중단한다. 직접 작품 주소의 제목 포커스는 준비 완료 또는 이미지 관람 전환 뒤에 이동한다. 모션 줄이기 환경에서는 CSS 반복 애니메이션을 끄고 완료 시 페이드 없이 덮개를 제거한다.

검증: TypeScript와 기존 44개 자동 검사를 통과했다. 실제 로컬 브라우저에서 데스크톱·390px 모바일 로딩, 메인 전환, 이미지 관람, 3D 재시도, 작품 직접 주소와 제목 포커스, 메인 복귀를 확인했다. 같은 실제 아치의 렌더 스타일은 연속 관측에서 stroke-dashoffset 381.332→138.898px로 바뀌었다. 모션 줄이기는 코드/CSS 검토이며 브라우저 환경 설정을 변경한 실행 검증은 아니다. 모델·재질·조명 설정은 수정하지 않았다. 기존 Gallery 청크 크기 경고는 남는다.

최종 UI 수정 뒤 배포 빌드를 다시 생성했다. 이번 작업은 로딩 UI 변경으로, Revision M의 첫 접속 성능 수치를 새 UI의 재측정 결과로 사용하지 않는다. 검수와 운영 확인의 상세 증거는 작업 폴더 `output/revision-n-loading/`에 보관한다.
